# 好友排序脚本规格

## 页面与排序栏

- 脚本在 `bgm.tv`、`bangumi.tv` 和 `chii.in` 的任意用户好友页及反向好友页生效。
- 从页面的完整好友列表读取好友；好友个人页路径 `/user/{id}` 中的 `{id}` 是主键，页面可见文本是展示名称。
- 在好友列表上方显示原站 `#browserTools` 风格的“按 加好友时间 名称 上次活跃 排序”栏，不显示额外的当前项视觉标记；窄屏允许自然换行。排序选项与状态文字在左侧靠左，正序/倒序按钮组在右侧靠右；名称方向显示“升序”/“降序”，时间方向显示“从旧到新”/“从新到旧”。
- DOM 不符合预期或列表为空时不修改页面。

### 原站样式基线

- 以 2026-09-01 的 [Bangumi `r771` 公开 CSS](https://bgm.tv/css/dist/bangumi.min.css?r771) 为核对基线。
- 原站 `#browserTools` 提供排序栏的上下边线、内边距和文字颜色；脚本保留该 ID 以复用这些外框样式。
- 原站的 `#browserTools .filters a` 规则为链接提供圆角和内边距，`.focus` 与 `:hover` 规则提供主题色背景和白色文字。脚本使用语义上更合适的 `<button>`，原站的链接规则不会直接生效，因此脚本需自行镜像相同的按钮交互样式。
- 原站 CSS 没有 `[aria-current]` 规则。脚本的 `aria-current="true"` 只表达当前排序选项的无障碍语义，不产生可见选中态。

## 排序语义

- 加好友时间：恢复网页默认顺序，即从新到旧。
- 名称：按访问者浏览器语言对展示名称自然升序排列，忽略大小写；同名时按好友主键排列，也可切换为降序，并随方向反转主键比较。
- 上次活跃：按默认时间胶囊全部动态中第一条动态的活跃时刻从近到远排列，也可从旧到新排列。活跃时刻统一为整数 Unix 秒；绝对 `title` 是年月日时分秒的权威来源。
- `title` 自带秒时完整采用其时间，不再参考相对文案。`title` 只到分钟时，仅当相对文案明确包含秒或为“刚刚”时才结合参考时间恢复秒；恢复出的候选时刻必须与 `title` 的年月日时分一致，否则秒回退为 `00`。
- 无时区的 `title` 固定按中国标准时间 `UTC+8` 解释，不受访问者浏览器时区影响。补秒所用参考时间优先取 HTTP `Date` 响应头，缺失或无效时取响应正文读取完成时的本机时间；参考时间截断到整秒。
- 相对文案接受“刚刚”，以及年、月、天、小时、分、秒中任意单单位或两个相邻且从大到小的单位；不接受逆序、跨级或三个单位。无法识别的文案仍采用有效的 `title`，秒记为 `00`。
- `X小时前`、`X小时X分钟前`、`X天X小时前`、`X月X天前`、`X年X月前` 等省略秒的文案不用于推测更小单位，活跃时刻采用 `title:00`。时间相同时始终保持网页默认相对顺序；无公开动态和未知活跃时间在任何方向都排在可靠时间之后，且二者保持网页默认相对顺序。
- 每次进入页面默认使用加好友时间的从新到旧；三个排序维度在当前页面内分别记忆上次选择的方向，但不持久化排序选择或方向。

## 懒请求与状态

- 从其他排序切换到上次活跃时，先用现有缓存排序，再增量刷新缓存缺失或获取时间已超过 24 小时的好友。超过有效期的旧缓存仍参与请求前排序，刷新失败时继续保留；没有待请求好友时不显示状态提示。
- 已经处于上次活跃且状态区空闲时，第一次再次点击显示 `5 秒内再次点击“上次活跃”以全量刷新`；提示不显示动态倒计时，并在 5 秒后消失。提示消失前再次点击会全量刷新当前好友列表，不考虑缓存是否有效。
- 从其他排序切换到上次活跃不计入全量刷新的两次点击。从上次活跃切到其他排序时，立即清除尚未触发的全量刷新提示并解除待命。
- 状态区正在显示获取进度或完成提示时，点击上次活跃不会触发增量刷新或进入全量刷新待命。从其他排序点击时仍切换并按缓存排序；本来已经处于上次活跃时则忽略该次点击。
- 增量或全量刷新待请求人数超过 400 时使用原生确认框。取消增量刷新后保留缓存排序且不显示状态提示；取消全量刷新后清除提示并解除待命，下次需重新点击两次。
- 最多并发 4 个请求，单个请求 15 秒超时。收到 `429` 时停止批次；连续 5 个 `403` 或 `5xx` 响应时停止批次。
- 请求期间在“排序”右侧显示 `正在获取 x/y`。完成后显示 `获取完成`；存在失败则显示 `获取完成，n 人失败`。完成提示均在 5 秒后消失。
- 全部请求结束后，仅在当前仍选择上次活跃时按当前方向统一重新排序。切换到其他排序不会取消后台任务；请求中可切换方向并立即重排当前缓存，不触发新请求。
- 增量刷新失败后，留在上次活跃并完成两阶段点击会全量刷新全部好友；只重试缓存缺失或过期的好友时，需先切到其他排序再切回上次活跃。不设置失败冷却。

## 时间胶囊与缓存

- 只有存在有效时间胶囊容器且没有动态的页面才记为“无公开动态”；该结果缓存 24 小时。
- 登录页、404、验证页、DOM 异常和首条动态时间缺失均视为失败，不用失败覆盖旧缓存。
- 缓存中的活跃时刻保存为整数 Unix 秒。升级到 v2 时删除旧 v1 缓存且不迁移旧版分钟级结果，使好友在下次选择上次活跃时重新获取。
- 缓存按当前域名和好友主键复用，不区分被查看用户、好友页或反向好友页；三个域名的缓存相互独立。
- 暂不限制缓存容量。`localStorage` 不可用、写满或存在损坏记录时，忽略无效数据并降级为当前页面内的内存缓存。

## 交付与验证

- 发布物为零运行时依赖的单文件 userscript。
- 使用 Node 内置测试验证稳定排序、缓存有效期、失败分类、400 人边界和最小时间胶囊 HTML fixture 解析。
