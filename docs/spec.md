# 好友排序脚本规格

> 本文同时记录当前实现和后续设计。标为“规划中”的条目不属于当前切片的验收范围。

## 页面与排序栏（当前实现）

- 脚本在 `bgm.tv`、`bangumi.tv` 和 `chii.in` 的任意用户好友页及反向好友页生效。
- 从页面的完整好友列表读取好友；好友个人页路径 `/user/{用户标识}` 中的路径段是稳定身份，页面可见文本是展示名称。
- 在好友列表上方显示原站 `#browserTools` 风格的“按 加好友时间 名称 上次活跃 喜好契合 完成条目数 排序”栏，不显示额外的当前项视觉标记；窄屏允许自然换行。排序选项与状态文字在左侧靠左，正序/倒序按钮组在右侧靠右；名称方向显示“升序”/“降序”，时间方向显示“从旧到新”/“从新到旧”，喜好契合和完成条目数方向显示“从低到高”/“从高到低”。
- 排序栏从 `#columnUserSingle` 上移到 `.mainWrapper`，置于 `.columns` 之前并占据整行，以使用主内容区域的可用宽度；好友列表仍保留在原有列中。
- DOM 不符合预期或列表为空时不修改页面。
- “喜好契合”是带下拉菜单的主按钮。主按钮文字保持不变；直接点击选择默认子项“同步率”，菜单顺序为“同步率 / 共同喜好数”。
- “完成条目数”是带下拉菜单的主按钮。主按钮文字保持不变；直接点击选择默认子项“全部”，菜单顺序为“全部 / 动画 / 书籍 / 音乐 / 游戏 / 三次元”。
- “完成条目数”下拉菜单在主按钮下方显示；鼠标悬停主按钮或菜单时保持打开，键盘焦点位于控件内部时通过 `:focus-within` 打开，触屏点击主按钮执行默认排序并借由焦点显示菜单，随后可以选择子项。

### 原站样式基线

- 以 2026-09-01 的 [Bangumi `r771` 公开 CSS](https://bgm.tv/css/dist/bangumi.min.css?r771) 为核对基线。
- 原站 `#browserTools` 提供排序栏的上下边线、内边距和文字颜色；脚本保留该 ID 以复用这些外框样式。
- 原站的 `#browserTools .filters a` 规则为链接提供圆角和内边距，`.focus` 与 `:hover` 规则提供主题色背景和白色文字。脚本使用语义上更合适的 `<button>`，原站的链接规则不会直接生效，因此脚本需自行镜像相同的按钮交互样式。
- 下拉菜单的圆角、间距、颜色、半透明背景、阴影、暗色主题和显隐动效镜像好友页“收藏”菜单；选项使用按钮语义，并补齐对应的键盘焦点样式。
- 原站 CSS 没有 `[aria-current]` 规则。脚本的 `aria-current="true"` 只表达当前排序选项的无障碍语义，不产生可见选中态。
- 下拉菜单中的当前子项同样只设置 `aria-current="true"`，不增加常驻可见选中样式。

## 排序语义

- 加好友时间：恢复网页默认顺序，即从旧到新。
- 名称：按访问者浏览器语言对展示名称自然升序排列，忽略大小写；同名时按用户标识排列，也可切换为降序，并随方向反转用户标识比较。
- 上次活跃：按默认时间胶囊全部动态中第一条动态的活跃时刻从近到远排列，也可从旧到新排列。活跃时刻统一为整数 Unix 秒；绝对 `title` 是年月日时分秒的权威来源。
- 同步率：按当前登录访问者与好友的同步率排序；共同喜好数：按当前登录访问者与好友的共同喜好条目数量排序。两者均要求登录，并按访问者标识隔离数据。
- 完成条目数：按全部、动画、书籍、音乐、游戏或三次元范围内状态为“完成”的条目数量排序；“全部”是默认范围。
- 完成条目数默认从高到低，方向文案为“从低到高”与“从高到低”。数值相同时保持网页默认相对顺序；未知值在两个方向均排在可靠值之后；明确取得的 `0` 是可靠值。
- 同步率和共同喜好数默认从高到低。
- `title` 自带秒时完整采用其时间，不再参考相对文案。`title` 只到分钟时，仅当相对文案明确包含秒或为“刚刚”时才结合参考时间恢复秒；恢复出的候选时刻必须与 `title` 的年月日时分一致，否则秒回退为 `00`。
- 无时区的 `title` 固定按中国标准时间 `UTC+8` 解释，不受访问者浏览器时区影响。补秒所用参考时间优先取 HTTP `Date` 响应头，缺失或无效时取响应正文读取完成时的本机时间；参考时间截断到整秒。
- 相对文案接受“刚刚”，以及年、月、天、小时、分、秒中任意单单位或两个相邻且从大到小的单位；不接受逆序、跨级或三个单位。单数位“分”也可写作“分钟”，“X分钟前”与“X分前”等价，“X分钟X秒前”同样恢复秒。无法识别的文案仍采用有效的 `title`，秒记为 `00`。
- `X小时前`、`X小时X分钟前`、`X天X小时前`、`X月X天前`、`X年X月前` 等省略秒的文案不用于推测更小单位，活跃时刻采用 `title:00`。时间相同时始终保持网页默认相对顺序；无公开动态和未知活跃时间在任何方向都排在可靠时间之后，且二者保持网页默认相对顺序。
- 每次进入页面默认使用加好友时间的从旧到新。各主排序按钮在当前页面内分别记忆上次选择的方向，但不持久化排序选择或方向。

## 懒请求与状态

- 从其他排序切换到上次活跃时，先用现有缓存排序，再增量刷新缓存缺失或获取时间已超过 24 小时的好友。超过有效期的旧缓存仍参与请求前排序，刷新失败时继续保留；没有待请求好友时不显示状态提示。
- 已经处于上次活跃且状态区空闲时，第一次再次点击显示 `5 秒内再次点击“上次活跃”以全量刷新`；提示不显示动态倒计时，并在 5 秒后消失。提示消失前再次点击会全量刷新当前好友列表，不考虑缓存是否有效。
- 喜好契合与完成条目数的各子项采用相同的两击规则，待命提示使用实际排序目标名称，例如 `5 秒内再次点击“共同喜好数”以全量刷新` 或 `5 秒内再次点击“动画”以全量刷新`；全量任务仍按所请求页面类型获取数据，进行中与完成提示仍使用主按钮名称。
- 从其他排序切换到上次活跃不计入全量刷新的两次点击。从上次活跃切到其他排序时，立即清除尚未触发的全量刷新提示并解除待命。
- 全量刷新是最低优先级操作，只能在状态区没有登录、完成或进行中提示时进入五秒待命。存在任一这些提示时，对当前排序目标的重复点击直接忽略，不创建待命提示，也不排队稍后处理。
- 五秒全量刷新待命提示的优先级低于所有其他提示；待命期间一旦产生登录、完成或进行中提示，立即清除提示并解除待命，之后需要在状态区重新空闲时点击两次。显示完成提示不阻止从其他排序切入远程目标时创建或扩充增量任务；新任务在后台执行，其进度受提示优先级控制。
- 同一页面类型的任务已经运行时，重复点击只切换字段、扩充集合或更新提示，不进入全量刷新待命。登录提示显示期间允许从其他排序切入并产生增量任务，但重复点击同样直接忽略。
- 增量或全量刷新在本次操作实际新增的好友页面请求数超过 400 时使用原生确认框。取消增量刷新后保留按现有缓存得到的排序结果；取消全量刷新后清除提示并解除待命，下次需重新点击两次。

### 主页字段任务与多任务调度（当前实现）

- 获取任务按请求页面类型划分，而不按排序主按钮或子项划分：上次活跃对应时间胶囊页任务；同步率、共同喜好数和全部完成统计范围共同对应用户主页任务。同一页面类型在任意时刻只有一个任务，切换到需要相同页面的目标时复用该任务，只改变进行中提示的主按钮名称和当前排序。
- 用户主页任务运行期间切换到另一主页字段时，将新字段缺失或过期的好友合并进现有待访问集合；已经访问或已在队列中的好友不重复加入。任务的待访问集合只扩充，不因切换字段而放弃先前尚未完成的好友。
- 用户主页任务的进度按唯一好友主页计数；切换字段扩充待访问集合时，分母随之增加，已完成数量保持不变。新字段没有引入好友时只改变提示名称，进度数字不变。
- 同一用户主页任务中，每位好友最多请求一次。响应会保留每个字段各自的解析结果；之后切换到本次响应中解析失败的字段时直接按失败计入，不在同一任务内重试，下一次新任务才可重试。
- 用户主页任务的失败人数按任务结束时最后选中的主页字段统计本任务实际访问过的唯一好友：请求失败、主页整体无效、该字段解析失败以及因批次停止而未尝试的好友均算失败；字段解析成功则算成功，即使请求最初由另一个字段加入。每位好友最多计一次，失败不覆盖该字段的旧缓存。
- 所有获取任务合计最多并发 4 个请求，单个请求 15 秒超时。切换到需要另一种页面的远程排序目标时，新任务抢占旧任务的待发送请求，但不取消旧任务已经发出的请求；旧任务保留进度，当前任务完成后再恢复。全局并发槽从旧请求释放后优先分配给当前任务。
- 切换到加好友时间或名称等不需要远程数据的排序时，后台批次继续执行且不被暂停；只有另一个确实需要发起请求的远程目标才能抢占。
- 切回被暂停任务所对应的排序目标时，该任务立即恢复为前台高优先级任务，并暂停另一页面任务的待发送请求；两个页面任务可反复交换前后台而不丢失各自队列、进度或结果。
- 收到 `429` 时停止当前及所有暂停任务，不再自动请求，并以一条展示 5 秒的 `请求受限，已停止全部获取` 取代这些任务的完成提示。连续 5 个 `403` 或 `5xx` 响应时只停止当前任务，并恢复先前暂停的任务。
- 请求期间在“排序”右侧显示 `正在获取“{主按钮名称}” x/y`。完成后显示 `“{主按钮名称}”获取完成`；存在失败则显示 `“{主按钮名称}”获取完成，n 人失败`。上次活跃使用“上次活跃”，同步率或共同喜好数使用“喜好契合”，任一完成统计范围使用“完成条目数”。完成提示均展示 5 秒。
- 用户主页任务的进行中与完成提示使用最近一次在前台选择的主页主按钮名称；失败人数只按任务结束时最后选中的主页字段计算，其他顺带字段的失败不计入该提示。
- 登录提示优先于完成提示，完成提示优先于进行中提示。不同页面类型的任务产生各自的完成提示；多个完成提示按完成顺序排队，每条提示成为队头时开始计时并保持可见 5 秒。登录提示覆盖当前完成提示时，该提示仍继续计时和出队而不延长；登录提示结束后显示届时仍在计时的完成提示，否则显示当前执行任务的进度。
- 全部请求结束后，仅在当前仍选择上次活跃时按当前方向统一重新排序。切换到其他排序不会取消后台任务；请求中可切换方向并立即重排当前缓存，不触发新请求。
- 任一页面任务完成后，仅当当前排序目标使用该页面的数据时，才按最新缓存和当前方向统一重排一次；用户主页任务不会因为解析了多个字段而重复触发完成或重排。
- 增量刷新失败后，留在上次活跃并完成两阶段点击会全量刷新全部好友；只重试缓存缺失或过期的好友时，需先切到其他排序再切回上次活跃。不设置失败冷却。
- 同步率、共同喜好数和完成条目数采用相同的增量刷新、两阶段全量刷新、状态提示、请求确认、并发、超时和批次停止规则。切换排序指标或完成统计范围会清除尚未触发的全量刷新提示。
- 扩充或创建任务时，只按本次操作实际新增的好友页面请求数判断大批量确认；超过 400 人时提示 `本次新增获取的好友数量过多（{n} 人），是否继续？`。取消时不加入新增请求，先前任务立即恢复执行和进度提示，新排序目标仍按已有缓存排列。
- 增量刷新只根据当前排序目标是否缺失或过期决定待请求好友；同一次好友主页响应中成功解析出的其他主页字段也一并更新并重新起算有效期，即使其旧缓存尚未过期。本次刷新所针对的排序目标不因此改变。
- 当前目标没有缺失或过期好友，且没有同页任务可复用时，不创建任务也不显示完成提示。
- 超过有效期的旧主页字段仍参与请求前排序，刷新或字段解析失败时继续保留并参与排序；过期只决定是否需要请求，不把可靠旧值降为未知。
- 未登录时选择同步率或共同喜好数，不发起批量请求并显示 `请登录后使用喜好契合排序`；完成条目数不要求登录。登录提示展示 5 秒且具有最高显示优先级，但不暂停已有任务或下面的完成提示计时，也不产生喜好契合完成提示。提示显示期间重复选择同步率或共同喜好数会被忽略且不重新计时；切换到完成条目数可以正常创建或扩充用户主页任务，其进度稍后按提示优先级显示。

## 时间胶囊与缓存

- 只有存在有效时间胶囊容器且没有动态的页面才记为“无公开动态”；该结果缓存 24 小时。
- 登录页、404、验证页、DOM 异常和首条动态时间缺失均视为失败，不用失败覆盖旧缓存。
- 缓存中的活跃时刻保存为整数 Unix 秒。升级到 v3 时删除旧 v1 缓存且不迁移旧版分钟级结果，并迁移仍在 24 小时有效期内的 v2 上次活跃记录。
- 缓存按当前域名和好友用户标识复用，不区分被查看用户、好友页或反向好友页；三个域名的缓存相互独立。
- 暂不限制缓存容量。`localStorage` 不可用、写满或存在损坏记录时，忽略无效数据并降级为当前页面内的内存缓存。
- v3 缓存按好友用户标识组织；上次活跃与后续字段独立校验并保存，为后续主页字段扩展提供承载。

## 用户主页数据与缓存

- 六个完成统计范围通过请求好友主页 `/user/{用户标识}` 取得。同一响应分别解析各范围；任何成功解析的范围都更新数值和自己的获取时间，解析失败的范围不覆盖旧值。
- 同步率和共同喜好数通过同一好友主页响应取得，解析和缓存规则与完成统计范围相互独立。
- 完成条目数不依赖访问者，仍组织在好友用户标识对应的记录下，并在好友页、反向好友页及不同被查看用户之间共享。
- 同步率和共同喜好数按当前登录访问者标识隔离并保存；访问者缓存键优先使用正整数 `CHOBITS_UID`；不可用时依次回退到非空 `CHOBITS_USERNAME` 和页头当前账号头像链接中的 `/user/{标识}`。三者均不可用时视为未登录，不从当前好友页 URL 推断访问者。
- 完成统计范围分别具有 72 小时有效期；恰好 72 小时时仍有效，超过 72 小时才过期。
- 同步率和共同喜好数分别具有 72 小时有效期。
- 有效好友主页包含 `#userStatsContainers` 时，空容器表示六个范围均可靠地为 `0`；存在有效 `#userStats_all` 时，缺失的单个分类块表示该分类可靠地为 `0`。容器缺失，或容器非空但缺少聚合块等结构矛盾，视为解析失败。完成项通过同一统计卡中 `.desc` 文本“完成”定位并读取 `.num`，不依赖颜色类或固定卡片位置。
- 完成统计范围与原站块 ID 的映射为：全部 `all`、动画 `2`、书籍 `1`、音乐 `3`、游戏 `4`、三次元 `6`；UI 顺序不照搬主页的 DOM 顺序。
- 同步率或共同喜好数节点缺失时不将其记为 `0`。明确解析出的 `0%` 或 `0` 是可靠结果。
- 完成条目数只接受非负安全整数；空文本、非有限数值或负的数量视为字段解析失败。
- 同步率接受页面披露的任意有限数值，包括小数和负值，不裁剪到 `0–100`；共同喜好数只接受非负整数。
- 用户主页 DOM 与解析行为以 2026-09-01 的实际页面及原站 CSS 为基线：完成统计块为 `#userStats_all`、`#userStats_1`、`#userStats_2`、`#userStats_3`、`#userStats_4`、`#userStats_6`；同步区域为 `.userSynchronize`，同步率位于 `.percent_text`，共同喜好数取自同区域包含“个共同喜好”的文本。同页获取方案另参考公开脚本 [bangumi 好友统计](https://greasyfork.org/zh-CN/scripts/36304-bangumi-%E5%A5%BD%E5%8F%8B%E7%BB%9F%E8%AE%A1/code) 与 [bangumi 社区助手](https://greasyfork.org/fr/scripts/527566-bangumi-%E7%A4%BE%E5%8C%BA%E5%8A%A9%E6%89%8B-preview/code)，实际实现使用 DOM 解析而非整页正则。
