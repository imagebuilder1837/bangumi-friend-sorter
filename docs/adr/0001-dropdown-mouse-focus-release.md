# 排序下拉菜单的鼠标焦点在指针离开时释放

排序下拉菜单（喜好契合 / 完成条目数）的显示来源有三个：JS 状态 `data-open`、CSS `:hover`、CSS `:focus-within`。触屏点击主按钮后靠显式 `focus()` 保留菜单（Issue #1 的明确需求），但桌面鼠标点击同样会留下 focus，导致鼠标移开后菜单滞留。我们决定显式记录最近一次接管焦点的输入模态（`pointerType` 或键盘），仅在“鼠标创建的 focus”且指针离开整个 dropdown 时主动 `blur()` 并收起菜单；触屏、触控笔与键盘创建的 focus 持久保留，CSS 三来源分工不变。

被拒的备选：直接在 `pointerleave` 中无条件关闭（会与 `:focus-within` 冲突，造成 `aria-expanded` 与实际 UI 不一致，且会抢走正在操作菜单的键盘用户）；删除主按钮点击后的 `toggle.focus()`（会重新破坏触屏保留菜单的需求，且依赖各移动浏览器对按钮点击 focus 的不一致行为）；用 `:focus-visible` 启发式判断输入来源（这是样式伪类，不是可靠的行为状态源）；用 `@media (hover: hover)` 判断（媒体查询描述设备主要输入能力，无法区分混合设备上的单次交互来源）。

后果：若未来把三个显示来源统一为单一 JS 状态机，需要重新推导本决策覆盖的全部输入组合行为（鼠标悬停、鼠标点击、触屏点击、触控笔、键盘、混合切换）。
