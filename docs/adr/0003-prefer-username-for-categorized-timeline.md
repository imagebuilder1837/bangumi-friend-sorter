# 分类时间胶囊请求优先使用用户标识路径

“和我贴贴”需要读取当前登录访问者的 `say` 与 `subject` 时间胶囊。Bangumi 页面同时暴露 `CHOBITS_UID`（数字标识）和 `CHOBITS_USERNAME`（用户标识）时，数字标识路径并不等价于用户标识路径：对 `/user/{CHOBITS_UID}/timeline?type=say` 或 `?type=subject` 的请求，站点会重定向到不带 `type` 的默认时间胶囊。分类参数丢失后，响应混合了不同类型的动态，解析器会把残缺或不属于当前分类的条目判为失败，整批统计因而无法发布。

我们决定：当前登录访问者的请求与缓存标识按非空 `CHOBITS_USERNAME`、有效 `CHOBITS_UID`、页头当前账号头像链接中的 `/user/{标识}` 依次回退。这个顺序只改变同时存在两种脚本变量时的选择；三者均不可用时仍按未登录处理，也不从正在查看的好友页 URL 推断访问者。

被拒的备选：继续优先数字标识——它在部分用户主页或缓存场景看起来更稳定，但分类时间胶囊的重定向行为会破坏请求语义；只在收到重定向后改写 URL——`fetch` 的最终响应已丢失原始分类意图，无法可靠区分正常默认时间胶囊与错误响应；从好友页所属用户推断访问者——查看他人好友页时会统计错误对象，违反“我”始终指当前登录访问者的定义。

后果：切换到用户标识优先后，已有按数字标识保存的访问者级缓存不会自动与用户标识缓存键合并，旧键会自然失效并在下一次成功获取后建立新键。若 Bangumi 将来改变数字路径的重定向行为，应重新核验请求和缓存键的兼容策略。
