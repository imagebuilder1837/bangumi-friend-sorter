# 刷新与任务状态

## 懒请求与状态

- 页面入口只创建远程排序会话并调用 `start`；后续排序交互只通过 `choose` 与 `changeDirection` 进入业务流程。当前排序目标、子选项、方向记忆、增量与两阶段全量刷新、登录前置条件、请求先后关系与提示优先级由会话统一拥有；任务登记表、状态机与排序栏内部节点均不向外暴露，也不存在全局事件总线。
- 从其他排序切换到上次活跃时，先用现有缓存排序，再增量刷新缓存缺失或超过[有效期](data.md#上次活跃与时间胶囊)的数据。超过有效期的旧缓存仍参与请求前排序，刷新失败时继续保留；没有待请求好友时不显示状态提示。
- 已经处于上次活跃且状态区空闲时，第一次再次点击显示 `5 秒内再次点击“上次活跃”以全量刷新`；提示不显示动态倒计时，并在 5 秒后消失。提示消失前再次点击会全量刷新当前好友列表，不考虑缓存是否有效。
- 从其他排序切换到和我贴贴时，先使用当前域名与登录访问者的完整缓存排序；缺少有效缓存时获取[完整统计范围](data.md#和我贴贴数据)。过期旧结果仍参与请求前排序，获取失败时继续保留。
- 已经处于和我贴贴且状态区空闲时，第一次再次点击显示 `5 秒内再次点击“和我贴贴”以全量刷新`；提示消失前再次点击会忽略缓存有效期并重新获取完整统计范围。全量成功才替换结果和获取时间，失败或中止不覆盖旧值。
- 喜好契合与完成条目数的各子项采用相同的两击规则，待命提示使用实际排序目标名称，例如 `5 秒内再次点击“共同喜好数”以全量刷新` 或 `5 秒内再次点击“动画”以全量刷新`；全量任务仍按所请求页面类型获取数据，进行中与完成提示仍使用主按钮名称。
- 从其他排序切换到上次活跃不计入全量刷新的两次点击。从上次活跃切到其他排序时，立即清除尚未触发的全量刷新提示并解除待命。
- 全量刷新是最低优先级操作，只能在状态区没有登录、完成或进行中提示时进入五秒待命。存在任一这些提示时，对当前排序目标的重复点击直接忽略，不创建待命提示，也不排队稍后处理。
- 五秒全量刷新待命提示的优先级低于所有其他提示；待命期间一旦产生登录、完成或进行中提示，立即清除提示并解除待命，之后需要在状态区重新空闲时点击两次。显示完成提示不阻止从其他排序切入远程目标时创建或扩充增量任务；新任务在后台执行，其进度受提示优先级控制。
- 同一页面类型的任务已经运行时，重复点击只切换字段、扩充集合或更新提示，不进入全量刷新待命。登录提示显示期间允许从其他排序切入并产生增量任务，但重复点击同样直接忽略。
- 增量或全量刷新在本次操作实际新增的好友页面请求数超过 400 时使用原生确认框。取消增量刷新后保留按现有缓存得到的排序结果；取消全量刷新后清除提示并解除待命，下次需重新点击两次。

## 主页字段任务与多任务调度

- 获取任务按请求页面类型划分，而不按排序主按钮或子项划分：上次活跃对应时间胶囊页任务，和我贴贴对应当前访问者时间胶囊的两个分类；同步率、共同喜好数和全部完成统计范围共同对应用户主页任务。同一页面类型在任意时刻只有一个任务，切换到需要相同页面的目标时复用该任务，只改变进行中提示的主按钮名称和当前排序。
- 用户主页任务运行期间切换到另一主页字段时，将新字段缺失或过期的好友合并进现有待访问集合；已经访问或已在队列中的好友不重复加入。任务的待访问集合只扩充，不因切换字段而放弃先前尚未完成的好友。
- 用户主页任务的进度按唯一好友主页计数；切换字段扩充待访问集合时，分母随之增加，已完成数量保持不变。新字段没有引入好友时只改变提示名称，进度数字不变。
- 同一用户主页任务中，每位好友最多请求一次。响应会保留每个字段各自的解析结果；之后切换到本次响应中解析失败的字段时直接按失败计入，不在同一任务内重试，下一次新任务才可重试。
- 全量刷新遇到仍在进行的同页面类型任务时扩充该任务而不是新建任务，因此遵守“每任务每好友最多一次”：任务内已尝试过的好友（含字段解析失败者）和已在队列中的好友不会重复请求，只追加真正新增的好友；解析失败字段要等下一次新任务才会重试。
- 用户主页任务的失败人数按任务结束时最后选中的主页字段统计本任务实际访问过的唯一好友：请求失败、主页整体无效、该字段解析失败以及因批次停止而未尝试的好友均算失败；字段解析成功则算成功，即使请求最初由另一个字段加入。每位好友最多计一次，失败不覆盖该字段的旧缓存。
- 所有获取任务合计最多并发 4 个请求，单个请求 15 秒超时。切换到需要另一种页面的远程排序目标时，新任务抢占旧任务的待发送请求，但不取消旧任务已经发出的请求；旧任务保留进度，当前任务完成后再恢复。全局并发槽从旧请求释放后优先分配给当前任务。
- 切换到加好友时间或名称等不需要远程数据的排序时，后台批次继续执行且不被暂停；只有另一个确实需要发起请求的远程目标才能抢占。
- 切回被暂停任务所对应的排序目标时，该任务立即恢复为前台高优先级任务，并暂停另一页面任务的待发送请求；两个页面任务可反复交换前后台而不丢失各自队列、进度或结果。
- 收到 `429` 时停止当前及所有暂停任务，不再自动请求，并以一条展示 5 秒的 `请求受限，已停止全部获取` 取代这些任务的完成提示。连续 5 个 `403` 或 `5xx` 响应时只停止当前任务，并恢复先前暂停的任务。
- 请求期间在“排序”右侧显示 `正在获取“{主按钮名称}” x/y`。完成后显示 `“{主按钮名称}”获取完成`；存在失败则显示 `“{主按钮名称}”获取完成，n 人失败`。上次活跃使用“上次活跃”，和我贴贴使用“和我贴贴”，同步率或共同喜好数使用“喜好契合”，任一完成统计范围使用“完成条目数”。和我贴贴的进度按已获取页数表达；完成提示均展示 5 秒。
- 用户主页任务的进行中与完成提示使用最近一次在前台选择的主页主按钮名称；失败人数只按任务结束时最后选中的主页字段计算，其他顺带字段的失败不计入该提示。
- 登录提示优先于完成提示，完成提示优先于进行中提示。不同页面类型的任务产生各自的完成提示；多个完成提示按完成顺序排队，每条提示成为队头时开始计时并保持可见 5 秒。登录提示覆盖当前完成提示时，该提示仍继续计时和出队而不延长；登录提示结束后显示届时仍在计时的完成提示，否则显示当前执行任务的进度。
- 全部请求结束后，仅在当前仍选择对应远程目标时按当前方向统一重新排序。切换到其他排序不会取消后台任务；请求中可切换方向并立即重排当前缓存，不触发新请求。
- 任一页面任务完成后，仅当当前排序目标使用该页面的数据时，才按最新缓存和当前方向统一重排一次；用户主页任务不会因为解析了多个字段而重复触发完成或重排。
- 增量刷新失败后，留在上次活跃或和我贴贴并完成两阶段点击会全量刷新对应完整范围；只重试缓存缺失或过期的数据时，需先切到其他排序再切回对应目标。不设置失败冷却。
- 同步率、共同喜好数、完成条目数和和我贴贴采用相同的两阶段全量刷新、状态提示、并发、超时和批次停止规则；和我贴贴不产生好友主页请求，也不按好友数量确认。切换排序指标或完成统计范围会清除尚未触发的全量刷新提示。
- 扩充或创建任务时，只按本次操作实际新增的好友页面请求数判断大批量确认；超过 400 人时提示 `本次新增获取的好友数量过多（{n} 人），是否继续？`。取消时不加入新增请求，先前任务立即恢复执行和进度提示，新排序目标仍按已有缓存排列。
- 增量刷新只根据当前排序目标是否缺失或过期决定待请求好友；同一次好友主页响应中成功解析出的其他主页字段也一并更新并重新起算有效期，即使其旧缓存尚未过期。本次刷新所针对的排序目标不因此改变。
- 当前目标没有缺失或过期好友，且没有同页任务可复用时，不创建任务，也不显示完成或进行中提示。
- 超过有效期的旧主页字段仍参与请求前排序，刷新或字段解析失败时继续保留并参与排序；过期只决定是否需要请求，不把可靠旧值降为未知。
- 未登录时选择同步率或共同喜好数，不发起批量请求并显示 `请登录后使用喜好契合排序`；完成条目数不要求登录。登录提示展示 5 秒且具有最高显示优先级，但不暂停已有任务或下面的完成提示计时，也不产生喜好契合完成提示。提示显示期间重复选择同步率或共同喜好数会被忽略且不重新计时；切换到完成条目数可以正常创建或扩充用户主页任务，其进度稍后按提示优先级显示。
