# 数据解析与缓存

本文件规定排序数据的身份、获取结果、解析、缓存有效性与迁移。排序如何使用可靠值见[排序规则](sorting.md)，请求何时启动及任务如何调度见[刷新与任务状态](refresh.md)。

## 身份与缓存隔离

- 缓存按当前域名和好友用户标识复用，不区分被查看用户、好友页或反向好友页；三个域名的缓存相互独立。
- 和 TA 贴贴完整结果按当前域名与贴贴接收方标识隔离，跨登录访问者、匿名访问、好友页和反向好友页复用；不同主页用户不互借结果。缓存代表最近一次成功获取的完整结果，切换账号不主动刷新，也不保证缓存对应当前账号的可见范围。
- 主页用户优先取当前页面 `#headerProfile .headerAvatar` 的个人页自链接，缺失或无效时从当前 `/user/{标识}/friends` 或 `/rev_friends` 路径提取；不从登录账号推断，不额外请求主页或维护别名映射，规范数字标识正常支持。
- 完成条目数不依赖访问者，仍组织在好友用户标识对应的记录下，并在好友页、反向好友页及不同被查看用户之间共享。
- 同步率和共同喜好数按当前登录访问者标识隔离并保存；访问者缓存键优先使用非空 `CHOBITS_USERNAME`，不可用时依次回退到正整数 `CHOBITS_UID` 和页头当前账号头像链接中的 `/user/{标识}`。三者均不可用时视为未登录，不从当前好友页 URL 推断访问者。这个身份独立于贴贴接收方；优先级的历史原因见 [ADR 0003](../adr/0003-prefer-username-for-categorized-timeline.md)。
- 契合指标映射在加载时整体校验：包含未知指标或无效指标记录的映射判为损坏并丢弃；访问者映射为空或某访问者的结果为空不是损坏；空条目不携带指标，不影响其他访问者有效数据的导入。

## 缓存格式与有效性

- 上次活跃缓存有效期为 24 小时；主页字段与和 TA 贴贴完整结果有效期为 72 小时。恰好 72 小时时仍有效，超过 72 小时才过期。主页字段各自计算有效期；同步率和共同喜好数也各自计算。
- 和 TA 贴贴完整范围任一必要页失败时不替换旧结果或续期。请求或解析失败不覆盖主页字段旧值；成功解析的各字段分别更新数值和获取时间。
- 暂不限制缓存容量，也不因过期而删除可靠旧结果；有效期只决定是否需要补取。

## 持久化与迁移

- 使用浏览器原生 IndexedDB；排序同步读取本页内存，不为每次排序查询数据库。排序偏好仍不跨页面保存。
- 初始化完成缓存读取与迁移后才挂载排序栏，等待期间原站列表保持可见。异步初始化最多等待 2 秒，超时或打开失败后本页只使用已读取的内存结果；迟到连接关闭，不回灌数据或触发重排。
- 仅自动导入 `localStorage` 的 v3 缓存，沿用原字段校验并保留原获取时间，格式有效的过期结果也导入；损坏字段不影响其他有效数据。v1、v2 完全忽略，不读取、不转换、不删除。
- 导入数据与迁移完成标记在同一事务提交，完整成功后才尽力删除 v3 旧键。失败保留旧键，本页可使用已读取的 v3 结果，下次打开页面再尝试。无法读取旧存储时不标记完成。
- 成功导入或确认没有可导入的 v3 数据后，不再读取或导入 v3；删除旧键失败也不重复导入，旧版页签后来写入的 v3 不再追赶。
- 好友任务结束时提交累积变更，按可独立更新的指标保存；和 TA 贴贴按接收方完整结果整体替换。没有逐响应或关页兜底保存，任务中途关页可能丢失尚未提交的结果。
- 不同页签更新不同好友、范围、访问者或指标不会相互覆盖。同一指标按获取时间保留较新的结果，时间相同时后提交者生效；本次不实时同步其他页签的内存或重排列表。
- 写入失败保留内存与未落盘变更，在下次正常提交时重试，不定时重试、不回退写入 `localStorage`，也不自动清空缓存或申请持久存储权限。
- 打开失败或超时后本页不自动重连。收到数据库升级通知时及时释放连接，本页继续使用内存，下次打开页面再尝试持久化。
- 存储故障静默处理，不弹窗、不新增状态提示，也不计入远程获取失败人数。

## 上次活跃与时间胶囊

- 上次活跃取自默认时间胶囊全部动态中第一条动态的活跃时刻。活跃时刻以整数 Unix 秒保存。
- 只有存在有效时间胶囊容器且没有动态的页面才记为“无公开动态”；其缓存有效期见[缓存格式与有效性](#缓存格式与有效性)。登录页、404、验证页、DOM 异常和首条动态时间缺失均视为失败，不用失败覆盖旧缓存。
- 绝对 `title` 是年月日时分秒的权威来源。`title` 自带秒时完整采用其时间，不再参考相对文案。`title` 只到分钟时，仅当相对文案明确包含秒或为“刚刚”时才结合参考时间恢复秒；恢复出的候选时刻必须与 `title` 的年月日时分一致，否则秒回退为 `00`。
- 无时区的 `title` 固定按中国标准时间 `UTC+8` 解释，不受访问者浏览器时区影响。补秒所用参考时间优先取 HTTP `Date` 响应头，缺失或无效时取响应正文读取完成时的本机时间；参考时间截断到整秒。
- 相对文案接受“刚刚”，以及年、月、天、小时、分、秒中任意单单位或两个相邻且从大到小的单位；不接受逆序、跨级或三个单位。单数位“分”也可写作“分钟”，“X分钟前”与“X分前”等价，“X分钟X秒前”同样恢复秒。无法识别的文案仍采用有效的 `title`，秒记为 `00`。
- `X小时前`、`X小时X分钟前`、`X天X小时前`、`X月X天前`、`X年X月前` 等省略秒的文案不用于推测更小单位，活跃时刻采用 `title:00`。
- 好友的公开时间胶囊结果在同域名不同被查看用户、好友页或反向好友页间共享；缓存键见[身份与缓存隔离](#身份与缓存隔离)。

## 和 TA 贴贴数据

- 统计当前域名下主页用户的吐槽与收藏时间胶囊各最新五页的完整结果，只计动态承载内容上的反应者，不计回复；保存全部反应者，不局限于当前好友列表。
- 未登录也可使用；每次请求携带当时浏览器的同源凭据，只统计该次访问可可靠读取的页面。匿名可见性与数字路径的站点观测见[外部核验](../external/tietie-timeline.md)。
- 最终响应须保持请求的同源地址、用户、分类和页码，正文激活分类导航也须匹配用户与分类；若正文含主页用户区，其身份不得冲突。分类丢失、身份不符、登录页或验证页均不能替代目标分类页面。
- 贴贴完整结果使用 `["tietieByRecipient", recipientIdentifier]` 持久化键，标识指贴贴接收方。v3 导入将旧 `tietie` 字段转换为新键，保留原用户标识、计数与获取时间，不改挂到当前主页用户，也不合并数字与文字标识。旧 IndexedDB 的 `["tietie", identifier]` 记录仅忽略、不转换或删除；缺失结果按正常刷新规则重新获取。
- 每条动态按内容链接、动态编号、表情容器完整标识的顺序选择去重依据；同一动态同时披露多个标识时登记它们的关联，后续缺少高优先级标识仍可识别重复。两个条目披露不同内容链接时，以内容链接为准，不因备用标识相同而合并；动态没有任何去重依据时直接累计。
- 完整统计范围和替换缓存的成功条件见[缓存格式与有效性](#缓存格式与有效性)及[刷新与任务状态](refresh.md#懒请求与状态)。

## 用户主页字段与缓存

- 六个完成统计范围通过请求好友主页 `/user/{用户标识}` 取得。同一响应分别解析各范围；任何成功解析的范围都更新数值和自己的获取时间，解析失败的范围不覆盖旧值。
- 同步率和共同喜好数通过同一好友主页响应取得，解析和缓存规则与完成统计范围相互独立。
- 完成条目数、同步率与共同喜好数的缓存有效期及访问者隔离规则，统一见[缓存格式与有效性](#缓存格式与有效性)和[身份与缓存隔离](#身份与缓存隔离)。
- 有效好友主页包含 `#userStatsContainers` 时，空容器表示六个范围均可靠地为 `0`；存在有效 `#userStats_all` 时，缺失的单个分类块表示该分类可靠地为 `0`。容器缺失，或容器非空但缺少聚合块等结构矛盾，视为解析失败。完成项通过同一统计卡中 `.desc` 文本“完成”定位并读取 `.num`，不依赖颜色类或固定卡片位置。
- 完成统计范围与原站块 ID 的映射为：全部 `all`、动画 `2`、书籍 `1`、音乐 `3`、游戏 `4`、三次元 `6`；UI 顺序不照搬主页的 DOM 顺序。
- 同步率或共同喜好数节点缺失时不将其记为 `0`。明确解析出的 `0%` 或 `0` 是可靠结果。
- 完成条目数只接受非负安全整数；空文本、非有限数值或负的数量视为字段解析失败。
- 同步率接受页面披露的任意有限数值，包括小数和负值，不裁剪到 `0–100`；共同喜好数只接受非负整数。
- 用户主页 DOM 与解析行为以 2026-09-01 的实际页面及原站 CSS 为基线：完成统计块为 `#userStats_all`、`#userStats_1`、`#userStats_2`、`#userStats_3`、`#userStats_4`、`#userStats_6`；同步区域为 `.userSynchronize`，同步率位于 `.percent_text`，共同喜好数取自同区域包含“个共同喜好”的文本。同页获取方案另参考公开脚本 [bangumi 好友统计](https://greasyfork.org/zh-CN/scripts/36304-bangumi-%E5%A5%BD%E5%8F%8B%E7%BB%9F%E8%AE%A1/code) 与 [bangumi 社区助手](https://greasyfork.org/fr/scripts/527566-bangumi-%E7%A4%BE%E5%8C%BA%E5%8A%A9%E6%89%8B-preview/code)，实际实现使用 DOM 解析而非整页正则。
