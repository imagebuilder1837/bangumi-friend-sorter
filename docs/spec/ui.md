# 页面与交互

## 页面与排序栏

- 脚本在 `bgm.tv`、`bangumi.tv` 和 `chii.in` 的任意用户好友页及反向好友页生效。
- 从页面的完整好友列表读取好友；好友个人页路径 `/user/{用户标识}` 中的路径段是稳定身份，页面可见文本是展示名称。术语见 [`CONTEXT.md`](../../CONTEXT.md)。
- 好友页不分页：即使好友数量极多（已以数万好友的页面核实），页面也一次性渲染全部好友条目，因此名次覆盖整个列表。名次只对可见好友（见 `CONTEXT.md`）编号；外部组件（如好友标签筛选）隐藏的好友项不参与编号。
- 每个好友项的名称块（灰线即原站 `ul.usersMedium div.userContainer strong` 的下边框，暗色主题为 `#666`）右下方显示加粗黑色小字名次，格式为 `#N`：初始化时按网页默认顺序标注，之后随每次重排（含切换排序目标、方向和刷新后的重排）立即更新。名次从 1 开始按当前展示顺序对可见好友连续编号，#1 永远是视觉第一位，不随方向翻转含义；平局规则见[排序规则](sorting.md#平局继承排序前顺序)，名次在可见好友中恒唯一。可见集合变化而顺序未变时只重写名次、不移动列表项，隐藏项徽章保留旧文本。排序栏以 `MutationObserver` 监听好友列表子树的 `style`/`class` 属性变化感知外部筛选切换（见 [ADR 0002](../adr/0002-rank-visible-friends-via-dom-observation.md)），回调重放最近一次渲染；无 `MutationObserver` 时降级为仅在后续渲染中修正名次。深色主题（`html[data-theme="dark"]`）下名次改用亮色以保证可读。
- 在好友列表上方显示原站 `#browserTools` 风格的“按 加好友时间 名称 上次活跃 和我贴贴 喜好契合 完成条目数 排序”栏，不显示额外的当前项视觉标记；窄屏允许自然换行。排序选项与状态文字在左侧靠左，正序/倒序按钮组在右侧靠右；名称方向显示“升序”/“降序”，时间方向显示“从旧到新”/“从新到旧”，和我贴贴、喜好契合和完成条目数方向显示“从低到高”/“从高到低”。排序标准见[排序规则](sorting.md)。
- 排序栏从 `#columnUserSingle` 上移到 `.mainWrapper`，置于 `.columns` 之前并占据整行，以使用主内容区域的可用宽度；好友列表仍保留在原有列中。
- DOM 不符合预期或列表为空时不修改页面。
- “喜好契合”是带下拉菜单的主按钮。主按钮文字保持不变；直接点击选择默认子项“同步率”，菜单顺序为“同步率 / 共同喜好数”。
- “完成条目数”是带下拉菜单的主按钮。主按钮文字保持不变；直接点击选择默认子项“全部”，菜单顺序为“全部 / 动画 / 书籍 / 音乐 / 游戏 / 三次元”。
- “完成条目数”下拉菜单在主按钮下方显示；鼠标悬停主按钮或菜单时保持打开，键盘焦点位于控件内部时通过 `:focus-within` 打开，触屏点击主按钮执行默认排序并借由焦点显示菜单，随后可以选择子项。
- 排序栏是对排序交互与呈现的唯一边界：调用方通过 `bind` 一次性注册选择排序目标与切换方向的领域意图回调，通过 `render` 幂等地传入当前目标、方向、子选项、最终提示文本与好友展示顺序；当前选择、方向文案、菜单选中态、刷新状态与好友名次由同一次渲染更新，调用方不持有排序栏内部 DOM 节点。展示顺序与可见集合均与上次相同时（例如仅有状态提示变化）不重复重排好友列表，也不重写名次。
- “按”与首个排序按钮之间、最后一个按钮（含下拉主按钮，后续新增按钮时以届时最后一个为准）与“排序”之间保持约一个半角空格（`0.25em`）的常驻间隙；按钮悬浮或聚焦时的背景色块不得与这些相邻文字相切。

## 原站样式基线

- 以 2026-09-01 的 [Bangumi `r771` 公开 CSS](https://bgm.tv/css/dist/bangumi.min.css?r771) 为核对基线。
- 原站 `#browserTools` 提供排序栏的上下边线、内边距和文字颜色；脚本保留该 ID 以复用这些外框样式。
- 原站 `#browserTools .filters a` 规则为链接提供圆角和内边距，`.focus` 与 `:hover` 规则提供主题色背景和白色文字。脚本使用语义上更合适的 `<button>`，原站的链接规则不会直接生效，因此脚本需自行镜像相同的按钮交互样式。
- 下拉菜单的圆角、宽度、间距、颜色、半透明背景、阴影、暗色主题和显隐动效镜像原站下拉菜单（对照 2026-09-01 的 `bangumi.min.css?r771`）：容器样式取顶部导航下拉（`#navMenuNeue li ul`）——竖向堆叠、圆角 15px、无边框；宽度收紧到最宽子项并保底时间线下拉（`ul.timelineTabs li ul`）的 `118px` 最小宽；子项几何取顶部导航下拉并在垂直方向微调——`padding:7px 15px`（原站 5px，加高药丸），`margin:2px 5px`（原站 5px，收紧相邻药丸间隙）；水平内边距与左右外边距保持原站值，`margin` 同时提供药丸距菜单边缘的内缩（菜单容器 `padding:4px 0`：原站为 0，上下微调以与子项间隙协调，左右仍由子项 margin 提供 5px 内缩）、药丸形 `border-radius:100px` 并在竖向 flex 中拉伸占满内容宽度；仅字号取时间线下拉的 `12px` 与 `line-height:100%`，避免继承正文字号行高导致行距过大。悬停与键盘焦点共用蓝色药丸（`#369cf8` 白字），不使用原站排序栏的粉色主色或 outline。这些竖向下拉样式在原站均被 ID 或结构祖先作用域锁定（或如 `ul.collect_dropmenu` 语义为横向布局），无法以类名复用，因此逐条镜像而非复用不匹配的类名。选项使用按钮语义，并补齐对应的键盘焦点样式。除[排序栏间隙](#页面与排序栏)要求外，样式细节不设样式断言测试锁定，以使样式可随时对照原站调整。
- 原站 CSS 没有 `[aria-current]` 规则。脚本的 `aria-current="true"` 只表达当前排序选项的无障碍语义，不产生可见选中态。
- 下拉菜单中的当前子项同样只设置 `aria-current="true"`，不增加常驻可见选中样式。
